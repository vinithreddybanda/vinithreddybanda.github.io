# Awwwards Inspiration

Use the Awwwards MCP configured in the repository's .mcp.json. The server is a visual reference library, not a source-code template.

## Workflow

1. Translate the brief into specific visual attributes: mood, palette, layout, interaction, and technology.
2. Use list_categories when filter vocabulary is unclear.
3. Search with 1–3 focused filters or phrases. Prefer 2–3 strong references, judged by actual screenshots rather than titles.
4. Inspect the shortlist with get_site_details for palette, technologies, design elements, description and awards.
5. Use create_design_brief for the selected slugs and the user's project goal. Extract shared signals and useful outliers into one original design direction.
6. For motion-led references, inspect get_site_elements and use video evidence. Posters show only one frame and are not sufficient evidence for animation.
7. If a reference URL is named, capture its full page and inspect its structure. Do not infer the whole site from a hero thumbnail.
8. State the design direction before coding. Tie each chosen mechanism to evidence and preserve accessibility and reduced-motion behavior.
9. Capture and analyze the completed build. Compare section order, backgrounds, heights, and mobile structure. Fix structural differences before visual polish.

## Useful MCP tools

- search_sites
- get_site_details
- get_site_elements
- create_design_brief
- capture_live_site
- analyze_page_structure
- record_site_motion
- get_motion_dna
- analyze_scroll_map

If the MCP server is not available, say so and use only verifiable references. Never invent MCP results.

## Guardrails

Use Awwwards work for study and inspiration. Do not copy a site's complete identity, layout, code, or proprietary assets. Build an original experience.
